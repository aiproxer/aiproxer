## Findings that shape the design

- **Seam.** `request.Transform` (stage `request_wide_shaping`) runs in `internal/core/runtime/executor_prepare_secure.go` on `backendClone`, the call **after** early conversation-view projection. The ingress/A-leg clone is separate, so a transform there is B-leg-only by construction. Pre-request admission, route hints, context estimation and billing run after it. Path virtualization uses later seams (attempt transforms, request-part hooks).
- **Steering carry-forward has a duplicate-occurrence conflict.** `conversationprojection.Reassert` derives request-local carried anchors from the frozen filtered baseline and early provenance, guarded by whole-trajectory structural compatibility and anchored-slot distinguishability (`lineage.go`). However, both resolution branches in `projection.go` consult them only when exact resolution fails. Task 6's unchanged executor regression rewrites the second of three identical user-role tool results: content identity omits tool-call ID, so stored occurrence 2 resolves to the third result despite distinct stable call IDs proving lineage to the second. `TestReassert_ExactResolutionRemainsTheNormalPath` explicitly pins that opposing precedence. Payload-only replacement is therefore not sufficient; design/task revision 5.1 proposes the narrow core-owned conflict change, subject to independent review, without weakening proof/refusal guards or changing global identity.
- **Why anchors matter here.** Anthropic tool results are user-role messages. `after_ingress_tail` steering (core terminal-decision continuation, interleaved thinking) anchors on the terminal user message, which in agent loops is often a tool-result message.
- **Canonical shapes and consumer evidence.** Legacy `PartToolResult` can carry both Text and Content: validation permits it, while Chat reads Content (decoding JSON strings) and Anthropic prefers Text. Therefore incoming dual carriers and auxiliary payloads cannot safely anchor or match duplicates. A feature-created replacement supplies Text plus JSON-string Content, so both existing encoders emit one identical marker. Item Output and ordered Parts must not alias: plain text Parts use framed count/kind/boundaries, not concatenation equality; other kinds/auxiliary fields stay verbatim. Original size sums payload bytes only, independently of comparison framing; savings subtract both replacement legacy carriers including JSON escaping. These owner-authorized F1–F3 corrections prioritize fidelity/interoperability without adapter production changes or requirement relaxation.
- **Large payload.** `request_transforms` is `PlaneAccessCanonicalRequired` in `internal/core/largebody/plane_catalog_generated.go`. Enabling the feature routes large bodies through the canonical path, which is safe.
- **Cache diagnostics wiring.** Collapse and write-churn detection are fed in production through the usage observer chain (`internal/infra/runtimebundle/candidate_compile.go:167`), and `NoteConfigGeneration` is called on reload. `ObserveSeamDigests` and `NoteStructuralCause` have **no production caller** today, so this slice cannot publish an elision cause; that is deferred.
- **Counters.** Feature factories receive only their YAML subtree. Process-owned feature collectors are constructed in `internal/standardplugins/featurehost/process.go` and registered through the generic metrics registry (keep-warm precedent). Path virtualization keeps its counters in a bundle-owned recorder that the standard factory does not export.

## Decisions taken against the handoff scope

- **Uneventful-result class deferred.** Empty results save nearly nothing, and classifying non-empty "no match" output needs per-tool knowledge the proxy does not have. V1 ships the lossless duplicate class only.
- **Maximum coverage per pass replaced by deterministic batching.** Per-pass caps need memory of the previous pass. The stateless batch frontier gives at most one discontinuity per batch. Retiring a delayed-result barrier can admit multiple batches even without a config change; the previous assertion that only enable/reconfigure passes do so was false. Structural-cause publication is still deferred. The coverage concern from Billion Context #2572 applies to lossy folds, and duplicate elision is lossless.
- **No persistence.** Decisions are a pure function of history and configuration, so restart, reload and multi-instance deployments agree without stored state.

## Prefix-stability argument

The old premise that every result before an unprotected result is unprotected is false: parallel round-1 calls `a,b,d` can return as `a`, then round-2 `c`, then delayed `b,d`. Skipping protected `c` batches `b,d`; appending round 3 admits `c` before them and can strand `d`. Monotone candidate sets are insufficient; we need prefix extension of the candidate stream.

For fixed config, define `T = indexed rounds - protect_recent_rounds`; stop at the first indexed result with `Round > T` (or end). All results participate in this barrier, irrespective of duplicate status or eligibility. Never batch later unprotected islands. Inside this safe prefix first occurrences anchor but never elide, and all otherwise eligible duplicates accumulate until the whole pending group reaches threshold. Ineligible prefix entries neither add savings nor reset the group; the withheld suffix adds nothing.

For any valid append-only ordering, old calls/results and their prefix resolution stay fixed; round count cannot decrease. The barrier cannot move left. All old prefix gates, earliest anchors, marker inputs and savings stay fixed. Later item references cannot remove an eligible old candidate: nonempty result IDs were already excluded, and empty IDs cannot be reference targets. Thus the old eligible stream is an exact prefix of the new stream, not merely a subset. Deterministic accumulation reproduces every old completed frontier and identical marker bytes. Only a pending subthreshold tail can combine with new candidates. This proves 4.1 without persistence; purity proves 4.2/4.3. Ordinary in-order sessions have no delayed islands and still elide retired rounds. Envelope/config/authority changes and rewrites are not this append-only case.

Processing failures must return sanitized fixed classifications after byte-exact rollback. Swallowing errors/panics makes generic FailOpen skip metrics and diagnostics disappear; it is not required for request success. The runner, not Handle, owns continuation. Never format/wrap the original payload in diagnostics or add request-derived labels.
