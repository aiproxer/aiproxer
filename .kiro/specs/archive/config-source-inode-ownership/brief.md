# Draft proposal: pin the accepted Linux configuration inode

**Status: historical pre-spec proposal, subsequently formalized and completed.** This document predates the formal spec; requirements, design, tasks, and `spec.json` now exist in this archived prerequisite spec. The archived owning spec remains archived.

## Problem and evidence

Issue #645 requires an atomic replacement to remain eligible after a rejected candidate. On Linux, `configsource` currently derives identity from device, inode, and statx birth time, then closes the opened file after each read. `ActiveSourceVersion` retains only identity and digest, so the accepted inode can be freed after rename and reused before the next recovery attempt. If reuse occurs inside ext4's coarse birth-time interval, the new physical file repeats the saved identity and is rejected as an in-place edit.

The mandatory commit run recorded this failure in `/tmp/lip-645-task-5_1-commit.log:163-166`: `TestFixedSource_AtomicReplaceWithRecycledInodeIsEligible` rejected the recovery replacement as `source_non_atomic_update`. The focused debugger reproduced 18 failures in 20 runs (2 passes, no skips); 971 of 1,000 unpinned ABA cycles repeated the birth time. Holding the accepted source descriptor pinned the original inode through 1,000 replacements, with zero original-inode reuse and zero pinned-identity changes. `FS_IOC_GETVERSION` had zero collisions in 1,000 cycles, but ext4 permits changing it when metadata checksums are disabled and provides no trustworthy unprivileged read-only capability check. Debug artifacts: `/home/mateusz/.cache/lip-dev-tmp/issue-645/configsource-debug-a3d80u4c`.

The VFS drops the inode only after its final reference; ext4 makes an inode number available only after inode teardown. Thus retaining a read-only descriptor for the accepted file prevents that inode number from being reallocated while it is the active baseline. This is an inference from the [Linux VFS inode lifetime](https://raw.githubusercontent.com/torvalds/linux/v6.12/fs/inode.c), [ext4 inode freeing order](https://raw.githubusercontent.com/torvalds/linux/v6.12/fs/ext4/ialloc.c), and [`unlink(2)` open-file lifetime](https://man7.org/linux/man-pages/man2/unlink.2.html). The ext4 version ioctl reads `i_generation`, while setting it is an owner-authorized mutation and is rejected on metadata-checksummed filesystems; it is not adopted as identity evidence ([ext4 ioctl implementation](https://raw.githubusercontent.com/torvalds/linux/v6.12/fs/ext4/ioctl.c)).

## Contract and platform boundary

This prerequisite refines [requirements 2.1 and 2.9](../versioned-runtime-reloadable-proxy-configuration/requirements.md), [Stable read protocol / unsupported-filesystem posture](../versioned-runtime-reloadable-proxy-configuration/design.md), and [tasks 1.2 and 2.1](../versioned-runtime-reloadable-proxy-configuration/tasks.md). Changed bytes on the accepted physical file remain rejected; a different physical file is eligible; identical identity and digest remain a raw no-op. Runtime reads must receive an explicit baseline; `nil` is reserved for bootstrap, never a running-host recovery fallback.

| Platform / handle capability | Startup | Runtime comparison |
| --- | --- | --- |
| Linux, positively identified ext4 kernel driver | Bounded stable read and retained read-only accepted-file owner | New `linux-ext4-dev-ino-lease-v1`; live provenance-checked baseline pin required |
| Linux, other filesystem or detector unavailable | Existing bounded stable startup read; explicit unavailable baseline, no retained pin | Fail closed as existing SDK `ResultSourceIntegrity` |
| Windows, existing `win-fileid` | Existing behavior | Preserve native scheme and runtime reload, without requiring the Linux lease |
| Other Unix, existing portable `dev-ino` | Existing behavior | Preserve existing adapter behavior; this prerequisite adds no uniqueness certification for that scheme |
| Other platforms currently unsupported | Existing behavior | Preserve existing unsupported behavior |

The Linux restriction scopes the proven allocator lifetime to the inspected ext4 implementation; it does not claim that all other filesystems violate the invariant. Support means the **ext4 kernel driver**, including ext-family disk formats mounted by that driver, not a claim about disk-format features. `fstatfs` magic `0xef53` alone cannot distinguish ext2, ext3, and ext4. Identify support read-only from the same open regular-file handle: `statx(fd, "", AT_EMPTY_PATH, STATX_MNT_ID)` with the returned mask checked; parse at most 1 MiB of `/proc/self/mountinfo`; require one matching mount ID, matching device major/minor, filesystem-type field exactly `ext4`, and corroborating handle `fstatfs` magic. Hold the file open throughout detection. Missing/malformed/ambiguous/truncated data, absent mount entry, unsupported syscall/mask, or mismatch means unavailable, never a guessed ext4 capability. No pathname-prefix mount matching, ioctl mutation, raw-block inspection, or unbounded fallback. The [handle statx API](https://man7.org/linux/man-pages/man2/statx.2.html) supplies mount ID; [mountinfo](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html) supplies driver type and device. Detection runs in the process mount namespace; a detached mount absent from mountinfo fails closed.

`ReadStable` retains regular-file checks and maxBytes+1 bounded read. Capture and revalidate identity, size and available modification/change timestamps on the **same candidate handle** before/after reading. Re-open the fixed path read-only for target validation and inspect that handle's regular-file mode, identity, size and matching stability metadata; avoid separate `os.Stat(path)` / identity lookups that can observe different targets. Linux active/candidate must be supported and on the same device; candidate/target must match physical identity and metadata. Pinning proves lifetime identity, not content-read stability. Every opened target handle closes on every exit.

## Ownership API and transaction

`SourceLeaseOwner` is the sole close-capable token. Its private synchronized core owns an `*os.File`, immutable identity/provenance, borrow count, close-requested/closing/closed state, completion notification and cached close error. Owner handoff is destructive (take-and-clear slots), rather than copying owner values. `SourceSnapshot` carries bytes/metadata plus an optional owner slot; taking its accepted baseline produces matching immutable `ActiveSourceVersion` metadata and moves that owner. Unsupported Linux baseline has explicit unavailable capability. Native schemes may legitimately have no owner.

`ActiveSourceVersion` has a private core reference and a **non-owning** `Borrow` API; it exposes no descriptor or close authority. Borrow validates the exported identity against the core's captured opaque identity, platform and scheme, then synchronously acquires an idempotent release token. Copying metadata adds no reference or close authority. Linux `ReadStable` holds this borrow from before candidate open through target validation and atomic classification. Public/direct `ClassifyAtomicReplacement` acquires its own validated active borrow for the entire comparison (and a candidate borrow for the lease scheme); the already-borrowed internal classifier avoids nested acquisition. Forged/missing/closed/closing/mismatched provenance fails closed. Candidate owner pins its identity until comparison completes or ownership transfers.

`RequestClose` is idempotent and rejects later borrows. At zero borrows it claims the file exactly once under the core lock, clears the file slot, closes outside the lock, then caches completion/error; otherwise the final release performs that sequence. `Close(ctx)` requests close and waits only through the supplied context for completion. There is no background goroutine, finalizer, unbounded later wait, raw-fd retention, or retry of `close(2)` after any result. A repeated close returns the cached result. Handle syscalls execute only while owned or borrowed; nobody calls `Fd` racing final close. A context bounds waiting for borrows, not the kernel's regular-file close syscall.

1. **Bootstrap:** `LoadBootstrapEffectiveWithSource` and its `bootstrapEffectiveLoader` seam return effective config, comparison metadata, optional owner and fixed overrides. Guard the snapshot immediately after read; decode/validation error or panic closes it. `buildHost` installs rollback ownership immediately after load, before nil-effective/access-mode/tracing checks. `bindHost` passes a takeable startup owner slot to `NewCoordinator`; validation errors leave it with the caller. `NewCoordinator` adopts it only when construction succeeds, with a construction rollback guard until return. Successful bind clears the caller slot. `afterBind` failure closes the resulting host and joins cleanup errors; earlier bind/build failure closes the startup owner with existing initial-failure cleanup. Remove `Host.activeSource` (currently a stale second metadata copy); comparison state lives only in `ReloadState`.
2. **One-shot:** `prepareInspect` (covering PrepareInspect, InspectRoutes and InspectInventory), ValidateStructural and ValidateDistribution consume the bootstrap owner immediately once effective loading has returned, before registry/tracing/plugin work. Return a cleanup error if that release fails, joined with any primary error. They retain no owner in an inspection session. Update every loader seam/test fixture mechanically; pkg/lipruntime still delegates to BuildHost.
3. **Runner, before publication:** guard candidate ownership immediately after `ReadStable`, including raw no-op, loader/classifier/compiler errors, cancellation and pre-swap publication rejection. Build and validate the effective/source update and its matching owner **before** calling Manager.Publish; preallocate the metadata copy and result bookkeeping. Production runner construction receives its concrete ReloadState adoption target from NewCoordinator; a missing target or invalid pairing rejects before publication. Raw no-op closes the candidate and retains the active baseline. Effective no-op uses the takeable outcome slot and ordinary Apply adoption, since no generation swap occurred.
4. **Publication boundary:** Manager.Publish currently swaps `m.active` before calling `startPublishedWork`, whose `StartPublished` callback can panic. Isolate that post-swap callback locally, including returned errors, without changing Publish's public signature: once swapped, Publish returns nil and preserves the active generation; report the post-commit callback failure through existing bounded lifecycle diagnostics. Never Discard the committed generation or return a precommit failure after this callback panic. In production, ResourceLedger.runStarts uses a panic-isolated start invocation for PhasePublish, records `startAttempted` before invocation, and converts panic to a bounded private error. execStartPhase then caches publishDone/publishErr, clears publishing and broadcasts on the normal error path; its PhasePublish completion guard also performs that finalization on unexpected unwind. It stops remaining starts on error, does not retry partially started hooks, and leaves existing generation quiesce/close responsible for attempted resources. This prevents a publishing flag stranded by panic from blocking cleanup. Prepare/Activate failures remain precommit rollback paths.
5. **Committed adoption:** install a deferred guard over the prevalidated update and non-nil prepared generation before Publish. Immediately after a successful Manager.Publish return, set the guard's committed flag with a plain assignment and read generation ID using the existing atomic Generation.ID accessor, then invoke a private `ReloadState.adoptPublishedSource` primitive **before** endStage/endAttempt or other fallible bookkeeping. Between Publish return and that flag assignment there is no callback, allocation, capability validation or fallible library call; genuine StartPublished panics have already been recovered inside Manager. The primitive uses the valid constructed state mutex, installs defer-unlock immediately after Lock, and consumes the already-validated owner slot while installing matching effective config, preallocated metadata, owner and prebuilt Published last-result/last-success fields together. No callbacks, injected seams, decoding, normalization, allocation or error-return path occurs in this critical section. This is a bounded callback-free handoff, not a claim that arbitrary mutex misuse or process-fatal faults can be recovered. It marks the update adopted and saves the displaced owner in the guarded receipt before unlocking, so recovery can distinguish an installed owner from a still-pending one without inspecting unrelated manager state. Displaced-owner cleanup and all diagnostics run afterwards through panic-isolated guards. The runner's outer recovery distinguishes precommit from committed: precommit closes its pending owner and reports the existing panic failure; committed recovery idempotently finishes this adoption and returns the prebuilt Published result, never disposing the committed source owner. After adoption the outcome carries an idempotent adoption receipt and no close-capable owner. Startup Publish has the same post-swap callback isolation; its source pin stays with the build rollback guard until successful coordinator bind, rather than using the reload adoption primitive.
6. **Coordinator/state bookkeeping:** for initial and coalesced attempts, guard returned **uncommitted** source slots until Apply consumes them. Coordinator panic, unapplied/empty/busy/rejected outcome or nil state closes only an uncommitted unused slot; a committed receipt refers to an already-adopted baseline and cannot be cleaned up as an unused candidate. Apply treats a Published receipt as confirmation and performs status/history bookkeeping without a second ownership transfer; effective Noop still destructively adopts its validated outcome slot. Keep the minimal adoption separate from fallible terminal bookkeeping and isolate observer callbacks; post-commit panic cannot replace Published truth or detach the matching baseline. Adoption target validity is established before Publish, so nil-state disposal is never permitted for a production committed update. Metadata clones remain borrowers only.

For the serialized host read path, retain at most one active pin, one candidate pin and one target-validation file; borrows add no descriptor. Capability detection adds one bounded transient mountinfo descriptor, closed before reading the candidate bytes. Tests count it separately. A direct external borrower may postpone a displaced pin's physical close; the bound applies to host-owned reads with no external retained borrow. All ownership paths must be integrated together before a normal implementation commit.

## Shutdown and errors

Preserve current `BeginShutdown` cancellation of admitted attempts, rejection of new admission/follow-ups, and manager publication guard. Do **not** BeginClose the baseline before an admitted attempt has completed: admission currently precedes ActiveInput/ReadStable. Extend attemptGate with a shutdown-only callback and protected `finalizing` / `finalizationDone` state. Register the callback atomically with shutdown under gate.mu, once. If an attempt exists, keep its open idleNotify and leave the callback pending. When Complete/Abandon clears that last attempt (after outcome cleanup), atomically claim the callback and set finalizing=true under the same lock; do not close idleNotify. If shutdown begins while initially idle, replace the already-closed idleNotify with a **new open channel** and claim/set finalizing before unlocking. Repeated BeginShutdown cannot replace this channel or claim another callback.

Invoke the claimed callback outside gate.mu; it detaches the state owner under state.mu and requests close using a guarded owner local. Its owner-release guard precedes optional diagnostics, so diagnostic panic cannot lose the detached pin. The callback wrapper has a deferred completion block: recover/sanitize panic and cache any finalization error; under gate.mu clear finalizing, set finalizationDone and close that notification channel exactly once, on success or panic. No gate/state lock nesting, helper goroutine or borrow wait occurs here. `WaitForIdle` must test **active == nil && !finalizing && (!shutdown || finalizationDone)** under gate.mu, rather than merely active==nil; otherwise it selects on the current channel or ctx.Done and rechecks. Complete/Abandon's ordinary non-shutdown idle path remains unchanged. Gate Snapshot busy includes finalizing, and shutdown still rejects admission. A waiter linearized before an initially-idle BeginShutdown may return normally; every waiter observing shutdown/finalizing must wait for completion or its deadline. An admitted-before-borrow attempt therefore still sees its baseline alive, with the existing Canceled/shutdown result on cancellation.

`Host.Close` remains BeginShutdown → WaitForIdle(ctx). Normal drain retrieves/waits for source completion with **that same ctx**, aggregates source errors, then performs existing manager/process/tracing sequencing. If WaitForIdle reaches its deadline, return promptly; the gate's registered callback remains armed and the admitted attempt's own completion requests close, even without another Host.Close call. If an already-live direct borrow delays physical close, its final release closes. A retry reads cached finalization/source completion errors and resumes existing cleanup; no cancellation-stripped source wait or helper goroutine. Source errors do not prevent remaining safe cleanup; existing manager failure restrictions on closing process services remain intact.

No new core LoadCategory, SDK result enum, or metric label is required. Unavailable/invalid Linux lease uses existing `CategoryNonAtomicUpdate`, mapped to `ResultSourceIntegrity`, with bounded private reasons (unavailable/closed/provenance) for path-free diagnostics. Never invent `source_reload_unavailable`, which currently maps to ResultInvalid. Post-swap start failures use existing cleanup/cleanup_failed lifecycle diagnostics with a bounded private post-publish-start reason and no raw panic value; they do not relabel Published. Runtime candidate, transient target, displaced-owner and deferred shutdown close failures use existing `ObserveLifecycle(stage="cleanup", result="cleanup_failed")`; bootstrap/one-shot return joined cleanup errors without starting a runtime observer. A target close failure before success returns existing partial-unreadable/source-integrity failure. Source-level cleanup failures accompany the returned error as a private typed cleanup marker, so the runner can emit existing cleanup telemetry without giving configsource an observer dependency; bootstrap joins the same marker as an error. Candidate cleanup after rejection/no-op retains the original result and reports lifecycle failure; displaced cleanup preserves committed publication. Deferred final-release cleanup records the cached error and emits the bounded lifecycle failure once via a panic-isolated sink installed on adoption. Host.Close reports source cleanup error alongside subsequent safe cleanup results; bootstrap rollback joins it with the primary error. No raw close error text enters SDK status, metrics, history or safe logs.

## Numeric acceptance and task plan

- **AC-01:** Linux accepted-file identity requires a live matching pin; no birth time/generation uniqueness fallback. Windows win-fileid and other existing non-Linux behavior remain intact (T1, T3).
- **AC-02:** Positive ext4-driver support is handle-bound and bounded; shared magic alone, missing mount ID/entry, over-limit mountinfo and wrong driver fail closed. Unsupported Linux startup still loads valid bytes (T1).
- **AC-03:** Regular-file, bounded size, same-handle before/after metadata and reopened-target checks persist. In-place changed digest rejects; identical identity/digest is raw no-op (T1).
- **AC-04:** Metadata cannot close; direct classifier and ReadStable both validate provenance and hold borrows throughout comparison. Closing/forged/missing Linux pins reject; concurrent final close executes exactly once and caches failure without fd reuse/retry (T1, T2).
- **AC-05:** Every bootstrap failure, nil-effective check, failed bind, successful coordinator adoption, afterBind failure and one-shot path has one explicit owner; stale Host metadata is removed (T1, T2).
- **AC-06:** Raw no-op, rejection, cancellation and precommit panic retain the active owner; Published/effective no-op transfer once. Inject deterministic StartPublished panic after asserting the manager active pointer changed, plus a production PhasePublish ledger-hook panic: result/status remain Published with the new generation, effective config, matching source metadata and live adopted owner; the old pin closes once and the new pin survives runner/coordinator/Apply cleanup. Inject a post-adoption bookkeeping/coordinator panic and assert the same receipt cannot dispose the baseline. Empty/busy/unapplied/nil-state cleanup applies only to uncommitted slots (T1, T2).
- **AC-07:** Shutdown tests pause deterministically after admission but before ActiveInput/borrow, and with a live borrow. Block outside-lock finalization with channel barriers in both initially-idle and active-at-shutdown cases; concurrent WaitForIdle callers must stay blocked despite active==nil, short contexts must expire promptly, and release/panic must notify all remaining waiters exactly once. Repeated BeginShutdown/Complete/Abandon cannot rerun the callback or close a channel twice. Normal drain/deadline preserve cancellation and cleanup at final completion/release without a helper goroutine or retry (T1, T2).
- **AC-08:** Inject close failures for target, candidate, bootstrap, one-shot, displaced active and deferred shutdown. Also inject StartPublished and PhasePublish start panic/returned error; assert Published truth, live matching baseline, ledger publishing cleared, cached publish failure/no start retry, and successful later quiesce/close without deadlock. Assert existing result/label vocabulary, publication preservation, error aggregation and one close call (T1, T2).
- **AC-09:** Supported-FS certification performs 1,000 rejected-candidate/recovery rename cycles, asserts every recovery eligible, original accepted inode never reused while pinned, and zero identity changes to the pinned file. It need not force impossible reuse of a pinned inode; pin lifetime and no reuse are the proof. No filesystem/reuse skip, sleeps or retry-until-pass (T1, T3).
- **AC-10:** Repeated bootstrap/one-shot/reload/noop/rejection/shutdown return to descriptor baseline; host pin bounds and transient detector handle bound are asserted (T1, T2).
- **AC-11:** Mandatory Linux hook and CI invoke the tagged certification; missing support or test population is fatal. Ordinary default/precommit graphs remain portable and include deterministic unsupported-startup/lifecycle tests (T1, T3).

No unused abstractions, placeholders, bypassed hooks or partial lifecycle commit. T1 ends only when normal mandatory hooks, supported-FS certification and relevant consumer checks pass.
