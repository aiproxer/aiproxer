# Task 20.6 — Execution Equivalence Closeout Delta and Phase 4 Recertification Evidence

This document records the completion of Phase 4 (Final Recertification and Rollout Evidence Refresh) of the execution equivalence remediation on branch `fix/large-payload-execution-equivalence`, closing out all findings identified during the adversarial equivalence review (Findings B1, B2, H3, M4, and M5).

---

## 1. Executive Summary

Following the initial delivery of the large-payload streaming fast path (#628, merge-base `9419ca4f`), an adversarial execution equivalence review identified five behavioral and resource equivalence gaps between the candidate wire execution path and canonical pipeline behavior:
1. **Finding B1 (Capture Body Materialization):** Whole-body `[]byte` slice materialization during candidate capture in `candidate.go:387` caused capture-through-open pipeline transient memory to scale with payload size (~2.5 MB @1 MiB, ~11.3 MB @5 MiB, ~50.4 MB @20 MiB).
2. **Finding B2 (Wire Race Engine Divergence):** A bespoke wire parallel race engine in `internal/core/runtime` diverged from canonical attempt machinery regarding winner criteria (requiring delta, not mere message start), handicap delays, cancellation independence, and backend panic isolation.
3. **Finding H3 (Routing State Advancement and Fail-Closed):** Two-turn weighted-first routing state was not updated on parallel race winner, and store persistence failure did not fail closed.
4. **Finding M4 (Spill File Leak on Pre-Existing Reader Closure):** Spill files were unlinked prematurely when `CompletedSource.Close()` was called while pre-existing readers remained open.
5. **Finding M5 (Truthful Terminal Capture Errors):** Capture reader opening failure returned `CaptureOutcomeDeclined` with `nil` error instead of terminal error, inducing an invalid canonical fallback on corrupted spools.

### Remediation Outcome (Phases 0–4)
- **Phase 0 (RED Repro):** 10 dedicated finding tests authored across 3 test files reproducing all defects against unchanged production code (`18b5be87`).
- **Phase 1 (Source-Only Accepted Lane):** `candidate.go` updated to return `res, nil, nil` directly for accepted candidates without memory slice materialization (`2de6a986`). Capture-through-open transient heap collapsed to a flat **~220–235 KiB** across 1 MiB, 5 MiB, and 20 MiB (ceiling: 458,752 B/op).
- **Phase 2 (Race Engine Consolidation):** Wire race engine collapsed directly onto canonical attempt machinery (`tryOpenParallelGroup` and `openNext`, seam `wireAttemptPayload`/`openWireAttemptTx`/`WireTakeStream`, net -217 lines; `8b45d618`).
- **Phase 3 (Shared Spill Lifecycle & Terminal Errors):** Implemented shared spill lifecycle tracking in `largebody` across readers and completed sources, plus `CaptureOutcomeTerminalError` with truthful terminal error propagation (`6771e21f`).
- **Phase 4 (Recertification & Docs Refresh):** Re-ran all finding tests, lane E2E suites, unit suites, full `archtest`, `internal/qa`, and repository-wide `go test -count=1 ./...` UNCHANGED. All suites pass 100% green with zero failures. Fuzz smoke targets run clean.
- **Production Status:** Configuration strictly defaults to disabled (`server.large_payload_fast_path.enabled: false`). Wire support is **NOT advertised** in default stock binaries (`WireSupportNotAdvertised` x3 pass). GitHub issue **#532 stays open**.
