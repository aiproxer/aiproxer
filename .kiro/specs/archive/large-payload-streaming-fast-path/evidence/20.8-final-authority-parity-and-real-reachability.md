## 3. Requirement B: Provenance, Wire Capabilities Contract, and Semantic Reachability

1. **Stock Origin Provenance Without Spoofable Markers & Composition-Boundary Validation:**
   - Spoofable `IsStock*` marker interfaces were eliminated in favor of unexported composition-origin flags passed exclusively from stock host construction sites.
   - `featurehost.Runtime` tracks unexported `conversationStoreStock bool`, set to `true` when created by `featurehost.ProcessServices`.
   - `featurehost.Runtime.CompileGeneration` sets `ConversationReaderStockOrigin: r.conversationStoreStock && r.conversationStore != nil` on `featurehost.CorePorts`.
   - `candidate_compile.go` calls `resolveCandidateConvReader(opts.CorePorts, ps.StandardFeatures)` at the candidate composition boundary. This verifies that any reader asserting `ConversationReaderStockOrigin: true` is genuinely identical to `ps.StandardFeatures.ConversationReader()`. If an overridden, custom, or forged reader is passed with `ConversationReaderStockOrigin: true`, the composition boundary overwrites stock origin to `false` (`TestStockHost_ForgedConversationReaderStockOrigin_OverwrittenAndDeclined`).
   - `build_large_body_assessor.go` sets `census.Ports.ConversationReaderFreshALegSupported = in.In.ConversationReader != nil && in.In.ConversationReaderStockOrigin`.
   - Custom / overridden readers lacking certified stock origin evaluate to `ConversationReaderFreshALegSupported = false`, triggering an authority static blocker that declines wire execution (`TestStockHost_CustomOverriddenConversationReader_Decline`).
   - Reload continuity preserves stock origin across configuration reloads (`TestStockHost_FastPath_ReloadContinuity`).
2. **Runtime Candidate Capability Negotiation (`lipapi.Negotiate`) & Elimination of Build-Time Subsumption:**
   - **Elimination of Frozen Build-Time Check (`isBackendCapsSubsumed`):**
     - The static build-time sampled check `isBackendCapsSubsumed` in `internal/infra/runtimebundle/build_executor.go` was eliminated. Previously, it statically sampled inventory models for `CapabilityStreaming` at executor build time, which risked false-accepting requests with unsupported capabilities (such as tools on a backend lacking `CapabilityTools`, or `parallel_tool_calls` on `o1`/`o3` models).
     - In `build_large_body_assessor.go`, `CapsResolverWireProofSubsumed` is now cleanly tied to capability-map presence (`capMap != nil`), shifting authoritative capability checks to candidate evaluation time.
   - **Frontend Derivation & Proof Stamp Binding:**
     - Frontend profile compilers (`openailegacy`, `openairesponses`, `openresponses`) derive exact `RequiredCapabilities` from client request shape and controls via `ControlRequirements{Delivery: lipapi.DeliveryModeFromClientStream(stream), HasTools: hasTools, ParallelToolCalls: parallelTools, ReasoningEffort: reasoningEffort, StructuredOutputs: structuredOutputs, ItemAuthoritative: itemAuthoritative}` without dropping parsed option flags. `hasHistoryTools(msgs)` inspects conversation history for `RoleTool`, `PartToolResult`, and JSON tool calls to guarantee history tool requirements are not dropped.
     - `RequiredCapabilities` is bound into `largebody.Proof`, authenticated via SHA-256 digest (`CapabilitiesDigest`) in `AssessmentStamp`, and validated against `WireRequestFacts` and `WireDomainFacts` (`stamp_validation.go`). Any tampering across initial assessment, domain facts, or late replacement returns `*StampInvariantError{Field: "required capabilities"}`.
     - Rebuilding domain facts under `UniversalOnly` in `executor_execute_large_body.go` preserves `RequiredCapabilities` and digests without dropping facts.
   - **Wire-Native Capability Resolution Contract (`ResolveWireCaps`):**
     - Replaced synthetic `lipapi.Call` construction with an explicit, wire-native capability resolver contract on `execbackend.Backend`: `ResolveWireCaps func(ctx context.Context, cand routing.AttemptCandidate) lipapi.BackendCaps`.
     - Stock backend adapters (`openaicompat`) share capability helpers (`openaicaps.ForHostedModelCompatibleReplay`) between canonical `ResolveCaps` and wire `ResolveWireCaps` without synthesizing a minimal `Call`.
     - Arbitrary Call-dependent custom resolvers (`be.ResolveCaps != nil && be.ResolveWireCaps == nil`) safely decline wire execution (`WireSupportReasonCapabilityUnsupported`) to prevent unauthorized wire dispatch (`TestCallDependentResolverDeclinesWireExecution`).
   - **Exact Upstream Call vs Raw Bytes Evidence & Canonical Immutability:**
     - **Wire Execution Path:** Spools raw, unmodified JSON bytes directly to upstream HTTP endpoints via `OpenWire`. Because wire streaming cannot perform option stripping or body parameter mutations on in-flight byte streams, any capability negotiation outcome other than `NegotiationLossless` (i.e. both `NegotiationReject` and `NegotiationDowngrade`, such as `parallel_tool_calls` on `o1`/`o3`) strictly declines wire execution with `WireSupportReasonCapabilityUnsupported`.
     - **Canonical Execution Path:** Fully decodes the request body into a typed `lipapi.Call`, where `ApplyNegotiatedDowngrades` safely soft-strips unsupported parameters (e.g. clearing `call.Options.ParallelToolCalls = nil` for `o1`/`o3`) before dispatching to upstream `Open`. Canonical execution semantics are unchanged and canonical package `pkg/lipapi` has zero diff (`diffzero`).
   - **Finite Controls & Capability Mapping Table:**
     | Control / Request Fact | Source Field / Representation | Derived `lipapi.Capability` | Negotiation Behavior on Wire vs Canonical |
     |---|---|---|---|
     | `Delivery` | Client stream flag (`DeliveryModeStreaming`) | `CapabilityStreaming` | Wire requires backend streaming; declines if missing. |
     | `HasTools` | Schema `tools` present or history contains tools (`RoleTool`, `ItemKindToolCall`, `ItemKindToolResult`, `PartToolResult`, JSON `tool_calls`/`function_call`) | `CapabilityTools` | Wire declines if backend lacks tools capability. Canonical hard-rejects (400) if required. |
     | `ParallelToolCalls` | Parsed option pointer `*bool` | `CapabilityParallelToolCalls` | Wire strictly declines on downgrade (`NegotiationDowngrade`, e.g. `o1`/`o3`); Canonical executes and soft-strips parameter. |
     | `ReasoningEffort` | Non-empty string (`reasoning_effort`) | `CapabilityReasoning` | Wire requires backend reasoning; declines if unsupported. |
     | `StructuredOutputs` | Structured output schema / response MIME | `CapabilityStructuredOutputs` | Wire requires backend structured outputs; declines if unsupported. |
     | `ItemAuthoritative` | OpenResponses item-authoritative client shape | `CapabilityOrderedItems` | Wire requires backend ordered-items support; declines if unsupported. |
     | `TurnPartShape` | `ContentPartImageRef` | `CapabilityVision` | Wire requires vision capability; declines if unsupported. |
     | `TurnPartShape` | `ContentPartFileRef` | `CapabilityDocuments` | Wire requires documents capability; declines if unsupported. |
     | `TurnPartShape` | `ContentPartVideoRef` | `CapabilityVideoInput` | Wire requires video capability; declines if unsupported. |
     | `TurnPartShape` | `ContentPartReasoning` | `CapabilityReasoningReplay` | Wire requires reasoning replay capability; declines if unsupported. |
     | `TurnPartShape` | `ContentPartExtension` | `CapabilityOpaqueExtensions` | Wire requires opaque extensions; declines if unsupported. |
   - **Capability Facts Package & Budget:**
     - Neutral package `internal/capabilityfacts` isolates fact structs, turn shapes, and derivation from `internal/core`, `internal/infra`, and `internal/plugins` (enforced by `import_rules.go`).
     - Line budget ceiling in `internal/archtest/budgets.go`: measured 271 lines, bounded at 296 lines (25 lines headroom).

## 4. Requirement C: Historical Fallback Proof on Resumed Session

1. **Scenario & Architecture:**
   - On the same stock host instance with fast-path enabled, a client submits:
     - **Turn 1 (Fresh Large Payload):** Fresh turn with clean baseline (> 1024 bytes). Evaluates wire-eligible; `openWireCalls` increments from 0 to 1, `openCanonicalCalls` remains 0. Response returns `X-LIP-Resume-Token`, `X-LIP-Session-ID`, `X-LIP-A-Leg-ID`.
     - **State Mutation:** Authoritative conversation store (obtained via `hostActiveExecutor(t, host)` and `conversationview.AsStore`) is updated with a `NeverBackend` tag and a `Steering` overlay for that `aLegID`.
     - **Turn 2 (Resumed Historical Turn):** Client sends a large payload with the resume token and session ID, containing the tagged message to drop and steering text.
2. **Verified Behaviors in `TestStockHost_HistoricalFallback_PersistedNeverBackendAndSteering`:**
   - **Precommit Decline:** `AssessLargeBody` declines wire execution because the session contains historical non-forwardable projection requirements.
   - **Canonical Projection & Filtering:** The request falls back cleanly to the canonical path where `snapshotAndProject` filters out the `never-backend-tagged-part` and prepends the steering overlay (`historical-steering-overlay-content`).
   - **Call Counters:**
     - `openWireCalls`: 1 (turn 1 wire stream; turn 2 did NOT invoke wire).
     - `openCanonicalCalls`: 1 (turn 1 did not call canonical; turn 2 incremented canonical open by 1).
   - **Held Permit Identity:**
     - The response header `X-Lip-A-Leg-ID` strictly matches the original `aLegID` from session turn 1, preserving permit continuity.
   - **Fail-Closed Snapshot Invariant:**
     - The executor validates that fresh sessions never have unexpected non-empty projections and fails closed if corrupted.
3. **Producer Transition Across Generations (`TestStockHost_HistoricalFallback_ProducerTransition_ReloadAndResume`):**
   - **Gen 1 Active Producer:** Feature enabled with registered `test-local-turn-producer` on `PlaneLocalTurnHandlers` claiming and tagging messages.
   - **Reload Reconfiguration:** Feature toggled off via configuration reload (`host.Reload`), yielding Gen 2 where `PlaneLocalTurnHandlersOccupied = false`.
   - **Resumption Invariant:** Resumed request (> 1024 bytes) under the existing session declines wire precommit under the SAME permit identity (`X-Lip-A-Leg-ID`), executes via canonical `Open` where tagged messages are stripped and steering overlays are applied.
   - **Subsequent Fresh Fast Path:** Subsequent fresh request (> 1024 bytes) under Gen 2 successfully executes over the wire fast-path (`openWireCalls` increments to 1), demonstrating clean producer lifecycle transition without leaking state across generations.

4. **Phase 2 & Phase 3 Heap Retention Benchmarks & Live GC Retained Analysis:**
   - **Harness Fixture Diagnosis & Resolution:**
     The previous evidence document noted that while `B/op` was flat at ~375 KiB, `runtime.MemStats.HeapAlloc` scaled at ~2.25 / 9.21 / 22.74 MiB. Diagnosis confirmed this was an artifact of the benchmark harness keeping the caller-owned `body := bench20MiBChunkedBody(...)` byte slice alive on the Go heap while reading global process `HeapAlloc`. The fast-path runtime itself never allocates or retains payload-sized buffers. Updating the benchmark harness to stream fixtures from temporary disk files (`writeDiskFixture`) completely eliminates the caller fixture from the Go heap (0 B fixture bytes).
   - **`BenchmarkLargePayloadHeap_PostCommitRetained` (Phase 2, disk fixture, `-benchmem -count=5`):**
     | Payload Size | Speed / Throughput | Cumulative Allocations (B/op) | Allocs/op (avg) | Genuine GC Live Retained Heap (`live-heap-B`) | Peak Heap (`peak-heap-B`) |
     |---|---|---|---|---|---|
     | **1 MiB** | ~47.3 MB/s (22.1 ms/op) | 392,175 B/op | 884 allocs/op | ~581 KiB (581,992 B) | ~1.61 MiB |
