# Task 12.1 — Explicit Bounded Runtime Wire-Facts Inventory

Task: 12.1 Convert Task 1.8 inventory into explicit bounded runtime wire facts:
- Only facts with named consumers; no shadow Call schema.
- Route/protocol/max-output/identity/session/source/rewrite/economic facts as required.
- Requirements: 19 (specifically 19.1, 19.2, 19.3, 19.4, 19.7).
- Upstream evidence: `.kiro/specs/large-payload-streaming-fast-path/evidence/1.8-call-census.md`.

---

## 1. Summary and Purpose

Task 1.8 performed a complete audit of every post-commit read, clone, and retention of `lipapi.Call` across accepted request execution (`.kiro/specs/large-payload-streaming-fast-path/evidence/1.8-call-census.md`). It identified that the primary retention to eliminate on the accepted fast path is the frozen `Call` triple in receive-turn facts (`baseline`, `ingressCall`, `conversationFilteredBaseline`) and per-attempt / terminal clones.

Task 12.1 converts that inventory into an **explicit, bounded runtime wire-facts inventory**.
Guardrails strictly applied:
1. **Named Consumers Only**: Every single field in the inventory names its exact downstream consumer.
2. **No Shadow Call Schema**: No unbounded prompt text, message trees, tool definition lists, attachment payloads, raw header bags, or general options maps are represented.
3. **Canonical Blockers Preserved**: Any port or capability that genuinely requires the full request content or trajectory (such as `LocalTurnHandlers`, `SecretGuardExecution`, custom `BillingIdentity` Call callbacks, or conversation projection snapshots) is explicitly NOT represented as a wire fact and remains a canonical blocker.
4. **Integration with Existing Wire Types**: Unifies and maps to existing wire types (`WireRequestFacts`, `WireDomainFacts`, `SessionInput`, `ClientTurnShape`, `ResponseFacts`, `SessionResponseCarrier`, and wire metering inputs `WireFrontendIngressInput` and `WireBackendIngressInput`).

## 2. The 8 Bounded Runtime Wire-Fact Domains

The runtime facts are embodied in `largebody.WireTurnFacts`, divided across the 8 required domains. Coverage is mechanical: `AssertConsumerCoverage` reflects over every direct field of all 8 domain structs and requires a matching non-empty `AuditNamedConsumers` entry (with explicit aliases for `Economic.CustomerPricingRef` → `economic.customer_pricing` and `Economic.ChargePolicyRef` → `economic.charge_policy`), and rejects stale keys; `AssertNoShadowCall` walks the full type graph rejecting shadow-Call field names and any `lipapi.Call` reference:

## 4. Unambiguous Canonical Blockers (No Shadow Call)

The following Task 1.8 sites require full prompt content, conversation trajectories, or arbitrary content callbacks. They **CANNOT** be represented as wire facts and remain canonical blockers:

1. **`PlaneLocalTurnHandlers` (`lipsdk/localturn`)**:
   - `Match(ctx, Call, Meta)` and `Handle(ctx, HandleInput{Call, ...})` inspect message text.
   - Disposition: Static blocker when occupied. No wire representation.
2. **`PlaneSecretGuardExecution` (`lipsdk/secretguard`)**:
   - `Evaluate(ctx, *Call, Meta, Services)` scans prompt text for secrets.
   - Disposition: Static blocker when active. No wire representation.
3. **`Custom BillingIdentity Call Callbacks` (`BillingIdentity.AccountID / CustomerPricingRef / ChargePolicyRef`)**:
   - Callbacks take `(ctx, Call) string` and inspect arbitrary request fields.
   - Disposition: Canonical blocker unless configured with stock bounded identity.
4. **`ConversationViewReader` (`conversationprojection.Reader`)**:
   - Trajectory-dependent snapshot reads.
   - Disposition: Blocker for content/trajectory uses.
5. **`SteeringWriterFactory` / `SteeringWriterResolver`**:
   - Returns `(lipapi.Call, Snapshot, error)`.
   - Disposition: Canonical blocker when steering is required.
6. **`CompactionDetector` (`RequestOpened(meta, Call)`)**:
   - Receives full `Call` on request leg.
   - Disposition: Canonical blocker when active.
7. **`hooks.Bus` request-content chains**:
   - Submit, request-part, tool, and attempt mutating hooks take `*Call`.
   - Disposition: Canonical blocker unless proven response-only.
8. **Detached-session execution**:
   - Auxiliary ingress retains full Call clones and independent lifecycle.
   - Disposition: Canonical only (Requirement 19.8).
