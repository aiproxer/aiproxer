## 1. Initial State (RED Phase)

Prior to the implementation of Task 14.4, `replayCandidate` in `internal/plugins/frontends/frontendpipe/candidate.go` called `wireExec.ExecuteLargeBody` directly without holdalive wrapping:

```go
// Prior code in candidate.go:
if wireExec != nil {
	execRes, execErr = wireExec.ExecuteLargeBody(ctx, assessment, capRes.Completed)
}
```

When differential tests were written in `candidate_keepalive_test.go` and executed before implementing the holdalive wrapper, streaming execution with enabled `PreRequestKeepalive` failed to emit the expected HTTP 102 Processing informational responses.

The failure directly proves that:
1. Streaming `ExecuteLargeBody` was not wrapped in `holdalive.Wait`.
2. On slow provider open with keepalive enabled, 0 informational responses were emitted.

---

## 3. Implementation (GREEN Phase)

1. Added `executeLargeBody` to `Config` in `internal/plugins/frontends/frontendpipe/pipe.go`:
   - Wraps streaming execution in `holdalive.Wait` with `PreRequestKeepalive`.
   - Bypasses `holdalive.Wait` for non-streaming execution (`!stream`).
2. Updated `replayCandidate` in `internal/plugins/frontends/frontendpipe/candidate.go`:
   - Evaluates `isStream := proofOut.Seeds().Stream || proofOut.Proof().Delivery == lipapi.DeliveryModeStreaming`.
   - Invokes `wireExec.ExecuteLargeBody` via `spec.executeLargeBody(ctx, w, wireExec, assessment, capRes.Completed, isStream)`.
   - Passes the generation/serve request `ctx` (carrying `StreamKeepaliveInterval`) downstream.
